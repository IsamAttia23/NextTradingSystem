# واجهات NEXT — دليل التنفيذ والتشغيل

تم بناء واجهات ASP.NET Core MVC للخدمات المكتملة، مع Bootstrap المحلي وJavaScript دون اعتماد على CDN.

## الواجهات

- لوحة تحكم بمؤشرات فعلية من خدمات التطبيق.
- المستخدمون: عرض، إنشاء، تعديل، تفعيل/تعطيل، وإسناد دور موجود.
- الأدوار: إنشاء وتعديل وحذف. يمنع التطبيق حذف أدوار النظام وإعادة تسميتها.
- الصلاحيات: إنشاء وتعديل وحذف، وترقيم صفحات على الخادم.
- صلاحيات الأدوار: ربط الصلاحية بالدور وإلغاء الربط.
- سلة المحذوفات: استعادة وحذف نهائي للمنتجات والعملاء والموردين والتصنيفات والوسوم والمستودعات، عبر الخدمة الموجودة. لا توجد واجهات CRUD لهذه المجالات لأن حالات الاستخدام التجارية لم تكتمل.
- تسجيل الدخول والخروج والتحقق الثنائي عبر تطبيق المصادقة أو رمز استرداد.
- حالات فراغ ونجاح وفشل ووصول غير مسموح.

لم تُضف واجهات لإنشاء الفروع؛ يجب وجود فرع لاختيارِه عند إنشاء مستخدم. البحث في الجداول يرشح الصفحة المعروضة فقط، ويذكر حقل البحث ذلك صراحةً. خدمات المستخدمين والأدوار والروابط الحالية تُرجع القوائم كاملة؛ يلزم تطوير استعلامات paginated على مستوى Application عند زيادة حجمها.

## SOLID وClean Architecture

- **Web:** Controllers للتنسيق مع الخدمات، نماذج عرض مستقلة، موارد ترجمة، Views، CSS وJavaScript. لا يستخدم Controllers الـDbContext أو EF Core.
- **Application:** حالات الاستخدام وقواعد التحقق والعقود. أُضيف عقد IBranchLookup، وأمر AssignUserRoleCommand، ومحول IRecycleBinSection لحصر الأنواع المدعومة دون انعكاس ديناميكي من مدخلات المستخدم.
- **Infrastructure:** تنفيذ جلب خيارات الفروع عبر EF Core. تبقى آليات الحفظ وIdentity في أماكنها.
- التحقق من صلاحية الفرع ومنع تغيير أسماء أدوار النظام داخل Application؛ لا يعتمد على إخفاء أزرار في الواجهة.
- WorkspaceController يجمع سلوك العرض المشترك فقط، وليس قواعد الأعمال.
- Table.cshtml و_ModalForm.cshtml و_Modal.cshtml وsite.js هي مكونات مشتركة. تُضاف شاشة جديدة بتعريف نموذج عرض وإجراءاتها، دون نسخ هيكل الجدول أو دورة فتح/إرسال الـModal.
- حدود الطبقات القديمة لم تُعد كتابتها بالكامل: ما زال Domain يحتوي أنواع Identity وفق البنية الحالية. هذا العمل لا يدّعي إزالة كل الدين المعماري السابق.

## اللغة والتصميم والخط

- العربية والإنجليزية عبر ملفات RESX، وحفظ اختيار المستخدم في Cookie، وتحميل Bootstrap RTL أو LTR تلقائيًا.
- استخدام CSS logical properties، قائمة جانبية تتحول إلى قائمة هاتف، وجداول قابلة للتمرير داخليًا، مع مراعاة لوحة المفاتيح والتركيز ورسائل الحالة.
- لوحة ألوان مستلهمة من هوية سوداني: الأزرق مع الأخضر واللون الليموني، مع علامة NEXT خاصة بالمشروع.
- مرجع الهوية: https://skyne.com/branding-agency-cases/telecom-branding-sudani-sudan
- خط Thmanyah Sans مُعرّف باستخدام local() فقط. إذا كان مثبتًا على جهاز المتصفح سيُستخدم؛ وإلا يُستخدم Segoe UI/Tahoma. **لم تُضمّن ملفات الخط في المستودع أو الحزمة.**
- الترخيص الرسمي يقيّد إعادة توزيع ملفات الخط وإتاحتها المستقلة عبر الويب: https://font.thmanyah.com/licenses
- لتوحيد الخط لجميع الزوار، يلزم توفير ترخيص يسمح بطريقة استضافة ملفات الويب ثم إضافة ملفات WOFF2 المصرّح بها وتعديل @font-face في site.css. الصور المرفقة تعكس الخط المتاح أثناء الاختبار، ولا تثبت وجود ثمانية على كل جهاز.
- التوجيه العام ورسائل الواجهة مترجمة؛ قد تبقى بعض تفاصيل أخطاء Identity/خدمات الأعمال الموروثة بالإنجليزية.

## التشغيل

1. افتح NextTradingSystem.slnx باستخدام Visual Studio الداعم لـ.NET 10.
2. اجعل NEXT.web مشروع بدء التشغيل.
3. اضبط ConnectionStrings:NEXTDatabase في User Secrets أو متغيرات البيئة، دون إدخاله في المستودع.
4. استخدم حسابًا إداريًا موجودًا. السياسة الافتراضية تتطلب الدور Admin.
5. إذا كان اسم الدور الإداري مختلفًا، اضبط Security:AdministratorRoles كمصفوفة في إعدادات النشر، مثل:
   `"Security": { "AdministratorRoles": ["YourExistingAdminRole"] }`
6. شغّل ملف التعريف http أو https. المسار الأول يعرض تسجيل الدخول للمستخدم غير المسجل.

الحساب المؤقت اختياري في Development فقط. فعّل DevelopmentAccess:Enabled واضبط DevelopmentAccess:UserName وDevelopmentAccess:Password في User Secrets أو متغيرات البيئة. يُنشأ فقط عند غياب مشرف Admin فعال، ويُرفض تسجيل دخوله وجلساته عند وجود مشرف رئيسي آخر. لا يُعاد تعيين كلمة مروره عند التشغيل. الوصول المؤقت محلي فقط. لا تضع كلمة المرور في المستودع. إدارة RolePermission لا تغيّر سياسة حماية هذه الواجهات تلقائيًا؛ هذه الواجهات محمية بسياسة ManageSecurity الإدارية.

جميع عمليات التعديل POST مع Antiforgery، وتُرفض إعادة التوجيه خارج التطبيق، وتستخدم جلسات Identity. لا تُعرض تفاصيل الاستثناءات الداخلية للمستخدم.

## التحقق المنفذ

- بناء Release ناجح دون أخطاء أو تحذيرات.
- 31 اختبارًا ناجحًا، تشمل اختبارات المعمارية والحفظ السابقة واختبار HTTP متكامل جديد.
- اختبار HTTP يستخدم MVC وRazor وIdentity Cookies وAntiforgery وخدمات Application الحقيقية مع قاعدة EF InMemory معزولة.
- غطى تبديل اللغة، منع CSRF وإعادة التوجيه الخارجي، حجب غير المسؤول، إنشاء/تعديل الأدوار، حماية اسم دور النظام، إنشاء/تعديل/حذف الصلاحيات، الربط وإلغاء الربط، إنشاء المستخدم ورفض الفرع غير الموجود، وترميز المحتوى لمنع XSS.
- مراجعة بصرية للعربية والإنجليزية، وحفظ نموذج عبر Modal في المتصفح، وفحص عرض هاتف 390px دون تجاوز أفقي للصفحة. صور المعاينة تستخدم بيانات اختبار.
- لا يُعد InMemory اختبارًا لقيود PostgreSQL أو اتصال بيئة التشغيل الفعلية. لم يُنفّذ اختبار OTP فعلي لمسار التحقق الثنائي.
- لا تغييرات على مخطط قاعدة البيانات، ولا Migration جديدة أو مطبّقة ضمن هذا العمل.

لإعادة الاختبارات من جذر المستودع:
```powershell
dotnet restore NextTradingSystem.slnx
dotnet test NextTradingSystem.slnx -c Release
```

## إضافات تجربة الاستخدام

- شاشة الدخول والتحقق الثنائي دون الشريط الجانبي.
- صورة المستخدم والترحيب باسمه في الشريط العلوي، مع أيقونات دلالية وشعار NEXT كأيقونة للموقع.
- اختيار الصورة من إنشاء/تعديل المستخدم. التحقق من المحتوى الفعلي على الخادم، دون الاعتماد على الامتداد أو MIME، بحد 7 MiB. يدعم محرك الصور صيغًا متعددة ومنها PNG وJPEG وGIF وWebP وBMP وTIFF وICO وSVG ذاتي الاحتواء. تُرفض الملفات التالفة أو غير المدعومة وSVG الذي يحتوي سكربتات أو مراجع خارجية. تُحفظ صورة PNG مصغرة حتى 512px دون metadata؛ الصور المتحركة تستخدم الإطار الأول.
- عقد معالجة الصور في Application وتنفيذه في Infrastructure باستخدام Magick.NET، وقراءة IFormFile في Web فقط.
- إشعارات مشتركة: أخضر للإنشاء، أزرق للتعديل والحذف والاستعادة، برتقالي للتنبيه، أحمر للأخطاء. أعلى اليمين بالإنجليزية وأعلى اليسار بالعربية.
- PWA بملف manifest وأيقونات تثبيت وService Worker. التخزين المؤقت للأصول العامة فقط، وصفحة عامة عند انقطاع الاتصال؛ لا تُخزّن الصفحات المصادقة أو بيانات المستخدم أو صورته. العمليات تتطلب الاتصال. التثبيت يتطلب HTTPS أو localhost ومتصفحًا داعمًا.
- اختبارات إضافية لـ7 صيغ صور وحد الحجم وSVG الآمن والخبيث، ورفع الصورة عبر HTTP وظهورها، ودورة حياة الحساب المؤقت.
- لا تغيير على المخطط. قد ينشئ التفعيل الصريح للحساب المؤقت سجلات مستخدم ودور وفرع محلي عند الحاجة.
